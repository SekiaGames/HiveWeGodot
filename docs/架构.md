# 架构

HiveWE 的 C++ 核心原样编译，界面与渲染换 Godot C#。地形算法、笔刷、地图读写这些逻辑一行不改。

独立的地图编辑器，与 SekiaWorld 没有依赖关系。

## 1. 分层

### 1.1 编进核心库的

`native/src` 下这五层进 `libhivewe_core.a`：

| 目录 | 行数 | 内容 |
|---|---:|---|
| `base/` | 7407 | 地形、装饰物、单位、区域、相机、路径图、阴影图 |
| `base/map/` | 1502 | 地图加载与保存的编排 |
| `base/triggers/` | 2383 | 触发器树、触发器数据、JASS 生成 |
| `brush/` | 3479 | 五类笔刷 + 地形算子 + undo 命令 |
| `file_formats/` | 1302 | w3e / slk / ini / 二进制读写 |
| `file_formats/mdx/` | 7127 | MDX 模型解析 |
| `resources/` | 1272 | 纹理、网格、骨骼资源 |

`render/`（3520 行 Vulkan）不编，`menus/`、`main_window/`、`object_editor/`、`trigger_editor/`、`model_editor/`、`asset_manager/`、`custom_widgets/`、`qt_imgui/` 也不编。

### 1.2 重写的

这些目录的代码都在做「把数据摆到控件上、把控件值写回数据」，换框架后整段作废。功能用 Godot 重做：

| 旧目录 | 行数 | 功能去向 |
|---|---:|---|
| `main_window/` | 1682 | 主窗口骨架用 `Control` 重搭。里面有约 400 行编排逻辑（新建地图、打开、保存、导出、导入高度图），搬进桥接层 |
| `menus/` | 3849 | 五个调色板用 `Control` 重做 |
| `custom_widgets/` | 913 | `QPainter` 自绘控件改用 `_Draw` |
| `object_editor/` | 2432 | 分类树用 `Tree`，字段表单由 `slk::build_meta_map()` 驱动 |
| `trigger_editor/` | 2379 | 树用 `Tree`，JASS 用 `CodeEdit`；`jass_tokenizer.cpp` 的 329 行纯词法可照搬 |
| `model_editor/` | 1835 | Godot 直接加载转换后的模型 |
| `asset_manager/` | 1445 | 资源树重做，目录枚举沿用 `hierarchy` 的查找优先级 |

`main_window/` 里那 400 行是业务逻辑，恰好写在窗口类里，必须单独搬到桥接层。

## 2. Qt 兼容层

核心层源码不改一行。`native/include/` 下放一组与 Qt 同名的转发头，`#include <QRect>` 这种原始写法直接生效。

```
native/include/
├── qt_shim.hpp      全部实现
├── QRect  QRectF  QPoint  QSize  QColor
├── QString  QStringList  QVariant  QSettings  QDir
├── QObject  QAbstractTableModel  QModelIndex  QAbstractProxyModel  QAbstractItemModel
├── QMouseEvent  QKeyEvent  QWheelEvent
├── QMessageBox  QWidget  QImage  QPixmap  QIcon  QPainter
└── QHeaderView  QTableView  QTreeView  QListView  QAbstractItemView  QStyledItemDelegate
```

语义上要对齐 Qt 的几处：

- `QRect::right() = x + w - 1`（闭区间），`QRectF::right() = x + w`
- `QString::arg` 替换编号最小的 `%N`
- `QSettings` 一律返回默认值。macOS 上没有注册表，`hierarchy` 读到的是全默认（SD 模式、允许本地文件）
- `QMessageBox` 打到 stderr
- `QProcess` 用 `popen` 实现，`waitForFinished` 是空操作（命令已经同步跑完）

Qt 信号在转换阶段改成 `std::function` 成员，共 7 个：`Brush` 的 `size_changed` / `selection_changed`，`DoodadBrush` 的四个，`RegionBrush` 的 `regions_changed`，`Terrain` 的 `minimap_changed` / `tileset_changed`。`emit` 展开为空，调用点不变。

## 3. 第三方依赖

brew 装的：

```bash
brew install cmake glm tbb abseil jpeg-turbo nlohmann-json stormlib bullet vulkan-volk
```

外加本机 Vulkan SDK（`include/vulkan` + `lib/libMoltenVK.dylib`）和 `third_party/` 下的 `ankerl/unordered_dense`、`vma`、`vkbootstrap`。

### 3.1 三个替身

有三个库拿不到现成的，或者拿来了也用不上，用最小替身顶替编译。它们都在 `native/include/` 下：

| 库 | 替身做什么 | 运行期影响 |
|---|---|---|
| **CascLib** | `CascOpenStorage` 等一律返回失败 | `hierarchy::open_casc()` 永远返回 false，代码走 MPQ 分支。CASC 是重制版的存储格式，本工程只处理 `.w3m` / `.w3x`（MPQ），这条路本来就不走 |
| **SOIL2** | `SOIL_load_image_from_memory` 返回 `nullptr` | SOIL2 只负责 DDS / TGA 贴图。War3 的贴图是 BLP，走的是 HiveWE 自己的 `blp_image` 分支（`resources/ground_texture.hpp:140` 那个 `if (!blp_image)` 之前），不受影响。真遇到 DDS 资源会抛异常 |
| **outcome** | `result<T, E>` 映射到 `std::expected`，`OUTCOME_TRY` 用宏展开 | 语义一致。`mdx` 那 304 处 `OUTCOME_TRY` 照常工作，失败时提前返回 `std::unexpected` |

另外四个是编译器补丁，不是替身：

| 缺的东西 | 补法 |
|---|---|
| `std::move_only_function` | alias 到 `std::function`（4 处，捕获的都是可拷贝对象） |
| `std::ranges::enumerate_view` | `native/include/std_shim.hpp` 里写了 40 行 view（4 处使用） |
| `std::execution::par` | 转换时去掉策略参数，算法串行跑（7 处） |
| `tracy/Tracy.hpp` | `ZoneScoped` 等展开为空 |

## 3.5 headless 化

核心编出来是给 Godot 用的，画面由 Godot 画，所以所有 Vulkan 副作用都要能跳过。用编译期开关 `HIVE_HEADLESS`（`native/CMakeLists.txt` 里 `-DHIVE_HEADLESS=1`）在 8 个位置短路：

| 位置 | 短路后 |
|---|---|
| `RenderManager()` 构造 | 直接 return，不建管线、不加载 click helper |
| `create_graphics_pipeline` | 返回 `VK_NULL_HANDLE`，不读 SPIR-V |
| `create_buffer` / `create_device_buffer` | 返回空 `Buffer` |
| `upload_buffer` | 直接 return |
| `upload_texture` | 返回空 `Image` |
| `UpdatableTexture::update` | 直接 return |
| `destroy_buffer_deferred` / `destroy_image_deferred` | 直接 return |
| `Bindless::add` | 自增槽位号，不写描述符 |

这些都在 `tools/decomod.py` 的补丁表里，重新生成 `native/src` 时自动套用，上游文件不动。

Qt 信号调用点也做了判空（`emit X(a)` → `if (X) { X(a); }`），否则没人接的时候会 `bad_function_call`。

## 3.6 版本兼容

HiveWE 的解析器本身覆盖了从 1.07 到重制版的所有格式分支：

| 格式 | 分支 |
|---|---|
| MDX | v800 / v900 / v1000 / v1100 / v1200 / v1300 / v1400 / v1600，`LATEST_MDX_VERSION = 1800` |
| war3map.doo | v7 / v8 / v13（v8 起有道具表，v13 起有 group_id、roll/pitch、光源） |
| war3map.w3i | v18 / v25 / v31（v31 起带 game version 字段） |
| war3map.j | 1.31 之前的触发器格式单独走 `Importing pre-1.31 trigger format` |

问题出在版本号本身。`MapInfo` 的四个版本成员没有初值：

```cpp
int map_version;
int editor_version;
int game_version_major;
int game_version_minor;
```

老地图的 `war3map.w3i` 版本低于 31，文件里没有 game version 字段，解析时不会覆盖这四个值，于是它们保持栈上的野值。野值恰好大于等于 1.32 时，`Doodads::load` 就按重制版布局去读，每条多读 4 字节 `skin_id`，2011 条累计偏移 8 KB，最后读越界。

补丁里给了默认值 1.27：

```cpp
int map_version = 1;
int editor_version = 6059;
int game_version_major = 1;
int game_version_minor = 27;
```

新建地图走 `load_defaults()`，那里仍然写 `write_game_version_major = 3`，不受影响。

## 3.7 1.27 的数据差异

HiveWE 面向重制版，1.27 的 MPQ 缺几个文件。缺的时候打日志跳过，不中断加载：

| 缺的 | 影响 |
|---|---|
| `Units/ItemMetaData.slk` | 道具对象元数据为空，对象编辑器里道具分类没字段 |
| `Units/UnitSkin.txt`、`Units/UnitWeaponsFunc.txt` | 单位皮肤的 INI，缺了单位属性少几列 |
| `doodads/terrain/clifftrans/*.mdx` | 悬崖过渡模型路径不同，悬崖照常渲染但过渡段没有模型 |

## 4. 桥接：C ABI

核心编成静态库再出 `.dylib`，导出一套 C 函数，C# 用 `[DllImport]` 调。不走 GDExtension：C++ 这边只管数据和算法，不碰场景树，走 C ABI 更短。

数据交换全是 POD 数组，没有 JSON、没有回调线程。

坐标统一用 **tile 浮点**（HiveWE 的原生单位），C# 侧乘 128 换成世界单位。这条写死在桥接层。

### 4.1 地形数据出口

渲染要的四个数组在 CPU 侧已经备好，`memcpy` 就行：

| 数组 | 内容 |
|---|---|
| `gpu_final_ground_heights` | 每顶点最终高度（`corner_height + layer_height - 2`） |
| `gpu_ground_texture_list` | 每 tile 一个 `uvec4`：四角纹理 id + 变体 |
| `gpu_ground_exists_data` | 每 tile 是否有地面（悬崖、坡道处为 0） |
| `gpu_water_exists_data` | 每顶点是否有水 |

BootyBay 193×97 = 18721 顶点、18432 tile，四份加起来不到 0.4 MB。

`uvec4` 的打包规则在 `terrain.ixx:1015`：取 tile 四角的纹理 id，排序去重；第一项高 16 位放变体号，其余项高 16 位放「这个 id 出现在哪几个角」的掩码。做 4 层混合前要读透这段。

### 4.2 已实现的

`native/bridge/` 下三个文件：

| 文件 | 内容 |
|---|---|
| `hive_c.h` | 纯 C 接口，`HiveMapInfo` / `HiveTile` 两个结构 |
| `hive_c.cpp` | 实现，管 MPQ 或目录数据源、解包、`Map` 的生命周期 |
| `hive_bridge.hpp` | `HiveBridge`，`Terrain` 的 friend，读它的私有成员 |

产物 `native/build/libhivewe.dylib`，2.9 MB。

```c
void*    hive_open(const char* map_path, const char* data_dir, char* error, int32_t error_size);
void     hive_close(void* handle);
int32_t  hive_save(void* handle, const char* target_dir, char* error, int32_t error_size);
int32_t  hive_map_info(void* handle, HiveMapInfo* out);
int32_t  hive_copy_heights(void* handle, float* out, int32_t capacity);
int32_t  hive_copy_tiles(void* handle, HiveTile* out, int32_t capacity);
int32_t  hive_copy_ground_exists(void* handle, uint8_t* out, int32_t capacity);
int32_t  hive_copy_water_exists(void* handle, uint8_t* out, int32_t capacity);
const char* hive_texture_id(void* handle, int32_t index);
```

`HiveTile.texture[4]` 原样保留 `uvec4`：低 16 位是纹理索引，高 16 位第 0 项放变体号、其余项放角掩码，`0xFFFF` 表示该项为空。

`hive_texture_id` 的第 `n` 个（`n == 纹理数`）返回 `"blight"`。

实测 BootyBay：193×97 顶点、7 种纹理（含 blight）、2011 装饰物、61 单位、高度 -1.00 ~ 6.63、4046 个有水顶点。

### 4.3 首批函数

| 分类 | 函数 | 对应 HiveWE |
|---|---|---|
| 生命周期 | `hive_open(map, game_dir)` / `hive_new(w, h, tileset)` / `hive_close` / `hive_save(path)` | `Map::load` / `Map::save` |
| 地图信息 | `hive_terrain_info()` | `Terrain::width/height/tileset_id` |
| 地形数据 | `hive_copy_heights(float*, n)` / `hive_copy_tiles(HiveTile*, n)` / `hive_copy_exists(uint8_t*, n)` | 上面四个数组 |
| 调色板 | `hive_texture_list()` / `hive_texture_thumbnail(i, size, out)` / `hive_cliff_list()` | `Terrain::ground_textures` / `cliffs` |
| 笔刷 | `hive_set_tool` / `hive_set_shape` / `hive_set_size` / `hive_set_param_f` / `hive_set_param_i` | `Brush::set_*`、各 `*Operator` |
| 指针 | `hive_pointer(x, y, state)`，state 0=按下 1=移动 2=抬起 | `Brush::mouse_*_event` |
| 撤销 | `hive_undo` / `hive_redo` / `hive_can_undo` | `WorldUndoManager` |
| 视图 | `hive_minimap_png(out, cap)` | `Terrain::minimap_image()` |
| 错误 | `hive_set_error_callback(cb, user)` | 替换 5 处 `QMessageBox` |

`hive_texture_thumbnail` 容易漏：纹理按钮墙贴的是真贴图缩略图，不是色块。

`hive_new` 不是「清空对象」，而是写一套最小文件再当普通地图加载（`hivewe.cpp:389`）：建临时目录、`Terrain::save_blank()` + `Doodads::save_empty()`、`load_map()`。`load_map` 里还要先 `resource_manager.clear()` 和 `skinned_mesh_globals.reset()`。

### 4.4 指针接口

笔刷吃的是世界坐标（tile 单位），来自全局 `input_handler.mouse_world`：

```cpp
glm::vec2 even = glm::floor(glm::vec2(input_handler.mouse_world) * position_granularity + 0.5f) / position_granularity;
```

C 侧只收 `(x, y)` + 状态位，不需要相机矩阵。C# 侧用 `Camera3D.ProjectRayOrigin/Normal` 与高度场迭代求交，换算成 tile 坐标传进来。

输入事件最终转给 `map->brush->*_event(ctx, event, delta)`，`ctx` 是 `WorldEditContext{terrain, units, doodads, regions, brush, pathing_map}`，桥接层自己拼。

```
godot/

├── HiveWeGodot.csproj     Godot.NET.Sdk 4.7.0，net8.0
├── HiveCore.cs            DllImport 封装
├── Main.cs                入口、相机、鼠标与键盘、保存
├── TerrainView.cs         地形与水面渲染、拾取、缩略图
├── EditorUi.cs            左侧面板、顶部工具条、状态栏
├── Shaders/*.gdshader     地形与水面
├── Main.tscn              只有一个 Node3D 挂 Main.cs
└── lib/libhivewe.dylib    构建产物，tools/build_godot_lib.sh 生成
```

C# 侧用 `NativeLibrary.SetDllImportResolver` 指定 dylib 的绝对路径，不依赖系统库搜索路径。

`libhivewe.dylib` 不链 MoltenVK。Godot 内嵌了一份 MoltenVK，再链接一份会撞 `MVKBlockObserver` 类，运行时报 "implemented in both"。headless 下根本不调 Vulkan 函数，去掉链接就干净了。

实测 BootyBay：193×97 顶点、7 种纹理、2011 装饰物、61 单位、高度 -1.00 ~ 6.63、4046 个有水顶点，与 `hive_abi_test` 完全一致。

## 4.6 笔刷与撤销

C ABI 里的笔刷接口：

| 函数 | 作用 |
|---|---|
| `hive_brush_move` | 设笔刷中心，地形 tile 坐标 |
| `hive_brush_size` | 边长，tile 单位，内部乘 4 换成 War3 的 1/4 tile 网格 |
| `hive_brush_shape` | 0 方形 / 1 圆 / 2 菱形 |
| `hive_set_texture_tool` | 纹理笔，参数是四字符 id |
| `hive_set_height_tool` | 抬升 / 降低 / 平台 / 起伏 / 平滑 |
| `hive_set_cliff_tool` | 悬崖升降、深水浅水、斜坡 |
| `hive_set_cell_tool` | 加水 / 去水 / 加边界 / 去边界 |
| `hive_brush_begin` / `apply` / `end` | 一次绘制，apply 按帧连调 |
| `hive_undo` / `hive_redo` | 走 HiveWE 的 `WorldUndoManager` |

**笔刷位置来自全局。** `Brush::get_position()` 读 `input_handler.mouse_world`（`base/camera.hpp` 里的单例），所以 `hive_brush_move` 就是往这个全局变量写一个坐标，不碰鼠标事件。`QMouseEvent` 那一整套留在上游，桥接层不经过它。

**工具互斥由上游决定。** 每个 `hive_set_*_tool` 后面调 `activate_operator`，它按 `can_combine` 关掉不兼容的旧工具。高度和纹理不能同时开，纹理和水可以。

**撤销快照全图。** `apply_begin` 把整张地形的 `Corner` 拷一份（18721 个，约 3 MB），`apply_end` 比对后压进撤销栈。所以一次拖拽只能得到一步撤销，符合 WE 的手感。撤销栈没有上限。

## 4.7 保存

两个出口：

| 函数 | 产物 |
|---|---|
| `hive_save` | 一个目录，里面是散装的地图文件 |
| `hive_save_map` | `.w3m` / `.w3x` 归档 |

`hive_save_map` 的流程：拷到 `/tmp` 下的 staging 目录 → 改 `hierarchy.map_directory` 指过去 → `Map::save` → StormLib 打包 → 恢复原目录。

三处要注意：

- **`Map::save` 写文件走 `hierarchy.map_directory`，不是它自己的 `filesystem_path`。** 两个都得改向后指，否则改动写进旧目录，新目录拿到的是拷贝时的旧文件。
- **打包要跳过 `(attributes)` 和 `(listfile)`。** 解包时 StormLib 会把这两个 MPQ 内部文件也解出来，逐个 `SFileAddFileEx` 时第一个就失败。
- **headless 下跳过 JASS 编译。** `Map::save` 里 `triggers.generate_map_script` 会调 `data/tools/clijasshelper.exe`，Windows 程序。跳过之后地图里原有的 `war3map.j` 原样保留，触发器改动不落盘。

保存出来的地图重新打开，高度与内存里的差 0.0019，是 `war3map.w3e` 用 16 位定点存高度带来的量化误差。

## 4.8 模型与装饰物

C ABI 里把 MDX 拆成扁平数组导出：

| 函数 | 作用 |
|---|---|
| `hive_model_from_doodad` | 按装饰物取模型，同一 id + variation 只解析一次 |
| `hive_model_info` | geoset 数、顶点数、索引数、包围盒 |
| `hive_model_geoset` | 该 geoset 在数组里的区间、双面、unshaded、alpha |
| `hive_model_geoset_texture` | 该 geoset 的 BLP 路径 |
| `hive_copy_model_positions/normals/uvs` | 整个模型拼成一个数组，geoset 用偏移引用 |
| `hive_copy_model_indices` | 按 geoset 取，索引是 geoset 内的局部值 |
| `hive_image_info_path` / `hive_copy_image_path` | 任意 BLP 解成 RGBA8 |

Godot 侧把每个 geoset 建成 `ArrayMesh` 的一个 surface，按模型分组建 `MultiMesh`。BootyBay 是 2011 个装饰物、62 种模型，1991 个能摆上去；61 个单位、18 种模型，59 个能摆上去。

单位走同一套模型接口，区别只在取模型的方式：`hive_model_from_unit` 调 `Units::get_mesh(id)`，缓存 key 加 `unit:` 前缀免得和装饰物的 id 撞。

### 坐标

`Doodad.position` 已经是 tile 坐标（`27.00, 17.50, 2.29`，第三个分量是高度），转 Godot 时交换后两位即可。

模型顶点不是：MDX 用 1/128 tile 作单位。树高 296 单位要除以 128 才是 2.3 tile。不除就会得到一堵墙。

### 三个坑

**slk 里的路径大小写和磁盘不一致。** `Doodads\Terrain\` 对 `Doodads/terrain/`，在区分大小写的卷上直接拼路径找不到。`mpq::resolve_path` 逐段做大小写不敏感匹配，替换掉 `hierarchy` 本地文件分支的原始拼接。

**`MDX::is_valid()` 对 1.27 的模型太严。** 它检查节点 id 必须是 0..n-1 的排列、父子不成环。老模型不满足，直接抛异常，`get_mesh` 静默回退到 InvalidObject（2 个空 geoset）。headless 下改成只打印。

**`SkinnedMesh` 构造里的 GPU 准备会越界。** `mdx->materials[i.material_id]` 没有边界检查，老模型的 material_id 可能越界。headless 下解析完 MDX 就返回，跳过图元打包与上传 —— 这部分本来就是给 Vulkan 用的。

### 替换贴图

树叶之类的贴图由 replaceable_id 查表得到，表里只给了秋天那份（`LordaeronFallTree`）。换张夏天或冬天的地图就找不到文件。回退逻辑按当前 tileset 的季节词在同目录里找（`L` → Summer、`I`/`N` → Snow、`A` → Ashen），找不到再用第一个能解码的。

## 4.9 路径图

`HivePathing` 一格一个字节，按 tile 的 4×4 细分：

| 位 | 含义 |
|---|---|
| `0x02` | 不可走 |
| `0x04` | 不可飞 |
| `0x08` | 不可建 |
| `0x20` | 不可采集 |
| `0x40` | 水 |

`hive_pathing_info` / `hive_copy_pathing` 导出原始字节，Godot 侧把它们画成一张 RGBA 叠加图塞进地形 shader 的 `pathing_overlay`。勾「显示路径」时按 `world_uv` 采样，红色叠在不可走的格子上。

只标「不可走且不是水」的格子。海洋在 `war3map.wpm` 里是 `0xCE`（不可走 + 不可飞 + 不可建 + 水 + 两栖），占 BootyBay 的 42%；全标出来整张图是红的，没有信息量。

BootyBay 不可走的陆地格 40380 / 294912，13.7%，落点和树丛、岩石对得上。

## 4.10 区域

`war3map.w3r` 里是矩形（left/right/top/bottom，tile 坐标）+ 名字 + 颜色 + 天气/环境音。

`hive_copy_regions` / `hive_region_name` 导出来，Godot 侧用 `ImmediateMesh` 画线段框。四条边按 0.5 tile 的步长采样地形高度，框贴着地形起伏走，不会插进山里。

材质开 `NoDepthTest`，被山挡住的部分也看得见 —— 编辑器里区域框本来就要始终显示。

区域默认显示，左侧面板的「显示区域」可以关。

## 4.11 放置装饰物

`hive_doodad_type_count` / `hive_doodad_type_id` 列可放置类型，`Doodads.slk` 的 469 个和 `DestructableData.slk` 的 247 个合并去重后是 716 个 —— 树、岩石这类都是可破坏物，只有可破坏物表里有。`hive_add_doodad` / `hive_remove_selection` 增删。

新增的 `Doodad` 要走一遍 `init(id, mesh, terrain)`：它算包围盒、绑模型、落路径图。不调的话新装饰物不会渲染。

左侧面板有个下拉列全部类型，选中后点地图就是放置，可以连续放。放完 `TerrainView.BuildDoodads()` 整个重建 —— 装饰物按模型分组装 `MultiMesh`，加一个就要重组，全量重建比增量维护简单得多，2000 个实例重建一次不到 100 ms。

下拉下面三个勾选框对应 `DoodadBrush` 的随机项：

```c
void hive_set_doodad_random(void* handle, int32_t flags);
```

位 1 变体从 slk 的 `numvar` 里随机，位 2 朝向在 0..2π 里随机后过一遍 `acceptable_angle`，位 4 缩放在 `minscale`..`maxscale` 里随机。变体不同拿的 MDX 也不同，所以要先定变体再 `get_mesh`。

## 4.12 拾取与选择

HiveWE 的拾取分两段：先 CPU 侧用模型 AABB 粗筛（`render_manager.pick_doodad_id_under_mouse`），再渲染到 picking buffer 读像素确认。

headless 下没有第二段，`hive_pick_doodad` / `hive_pick_unit` 只做粗筛，取距离最近的命中。对树这种细高模型，AABB 比实际轮廓宽一点 —— 点到树冠旁边的空气也会选中，但不会漏选。

四个细节：

- **射线换到模型单位。** 模型顶点是 1/128 tile，射线起点和 doodad 位置都乘 128 再比，避免两套单位混算。
- **轴序。** Godot 是 (X, Y高, Z)，War3 是 (x, y, z高)。入口转一次，出口（`hive_selection_box`）再转回来。
- **朝向。** 渲染用 `Rotated(Up, -angle)`，拾取用 `rotate(-angle, z轴)`，两边一致才会重合。
- **AABB 用 8 个角点变换。** 有非等比缩放时不能只变换 min/max，`transform_aabb_non_uniform` 就是干这个的。

选中后在状态栏显示类型和 id，视野里画一个黄色线框（`ImmediateMesh`，12 条边，开 `NoDepthTest`）。多选时把所有包围盒的边拼进同一个 `ImmediateMesh`，一次画完。

框选对应 `DoodadBrush::query_area`：

```c
int32_t hive_query_area(void* handle, float x0, float y0, float x1, float y1, int32_t is_unit,
                        int32_t* out, int32_t capacity);
```

矩形两个角由调用方给，C 侧自己归一化，从右下往左上拖也算数。命中判定用对象的位置是否落在矩形里，不看包围盒 —— 上游就是 `area.contains(i.position.x, i.position.y)`。

按下时命中对象就拖动它，没命中就开始拉框。拖框过程中实时更新选择并重画矩形；Shift 往选择里加，Alt 从选择里减，都不按就整体替换。选择列表同时只有一种对象类型，框选查装饰物，点选可以选中装饰物或单位。

## 4.13 删除对象

`hive_remove_selection` 不是简单 erase —— 先把对象快照塞进 `DoodadDeleteAction` / `UnitDeleteAction`，压进 `world_undo`，再按 `creation_number` 把整组从列表里删掉。撤销时这个 action 把对象 append 回列表并重刷路径图。整组只算一次撤销。

注意 `DoodadDeleteAction` 的 redo 是 `resize(size - n)`，只在「删除后立刻撤销再重做」这个顺序下成立 —— 因为 undo 是往尾部追加。直接连续删除两次再撤销一次，恢复的顺序会和原来不同。上游就是这个行为，照搬。

选择对象后按 Delete 删除，Ctrl+Z 撤销。

## 4.14 拖动对象

对应 `DoodadBrush::mouse_move_event` 的 `dragging` 分支。

```c
int32_t hive_begin_group(void* handle, int32_t is_unit, const int32_t* indices, int32_t count, float x, float y);
int32_t hive_move_group_to(void* handle, int32_t is_unit, float x, float y);
int32_t hive_rotate_group_to(void* handle, int32_t is_unit, float x, float y);
int32_t hive_end_group(void* handle, int32_t is_unit);
```

`begin` 存一份整组快照并记下鼠标位置，`move_to` 按「本次鼠标 - 上次鼠标」平移全组，每个对象重新贴地形（`interpolated_height`），`end` 用 `DoodadStateAction` / `UnitStateAction` 记下前后差异压进撤销栈，撤销时按 `creation_number` 匹配恢复。

组里只要有一个带路径图的对象，位移就吸到 0.5 格：`round(mouse * 2 + 0.5) / 2 - 0.25` 两头各算一次再相减，这是上游的自由/吸附两套位移。

拖动过程不重建整个装饰物渲染 —— 2011 个实例重组一次要几十毫秒，跟手会卡。改成给每个选中对象建一个 `MeshInstance3D` 幽灵（`TerrainView.ShowGroupGhost`），每帧从核心重新读一次位置摆上去，原来的实例留在原位，松开后统一重建。

## 4.15 旋转对象

`hive_rotate_group_to` 对每个对象走 `Doodad::acceptable_angle`：按 slk 里的 `fixedrot` 和对象自己的路径图把目标角度吸附到允许的朝向。树这类 `fixedrot` 是 90 度的对象转不动，单位不受约束。

角度用 `atan2(鼠标 - 对象中心)` 算，和 HiveWE 的 `mouse_move_event` 一致。吸附后还要调一次 `acceptable_position`，因为朝向变了，跟路径图对齐的锚点位置也得跟着挪。

交互是 Ctrl + 左键拖动，共用 `begin_group` / `end_group`，撤销按状态差异记录。

## 4.16 复制粘贴

对应 `DoodadBrush::copy_selection` / `place_clipboard` / `render_clipboard`。

```c
int32_t hive_copy_selection(void* handle, const int32_t* indices, int32_t count);
int32_t hive_clipboard_count(void* handle);
int32_t hive_copy_clipboard(void* handle, HiveDoodad* out, int32_t capacity);
void    hive_clipboard_anchor(void* handle, float* out);
int32_t hive_place_clipboard(void* handle, float x, float y);
const char* hive_clipboard_id(void* handle, int32_t index);
int32_t hive_model_from_clipboard(void* handle, int32_t index);
```

剪贴板存 `Doodad` 的整份拷贝，连 `mesh`、`skeleton`、`pathing` 一起。复制时记下这组的平均位置当中心点，放置时中心点对齐鼠标。

放置照抄上游的三步：

- 位置先用 `Doodad::acceptable_position` 吸附。整组一个开关：只要组里有一个带路径图的对象，全组都吸到 0.5 格。
- `creation_number` 重新发号，用 `++Doodad::auto_increment`。
- 全部塞进一个 `DoodadAddAction`，一次 Ctrl+Z 收掉整组。这个 action 的 undo 是 `resize(size - n)`，同样依赖「新对象在尾部」。

预览用 `MultiMesh` 按模型分组，每帧按当前鼠标重算每个实例的位置和贴地高度，不改动剪贴板里的原坐标。

交互是 Ctrl+C 复制选中、Ctrl+V 进粘贴模式、左键整组放下、Esc 取消。框选多选后直接复制整组。

单位另有一套剪贴板，函数和语义都对称：`hive_copy_unit_selection` / `hive_unit_clipboard_count` / `hive_copy_unit_clipboard` / `hive_unit_clipboard_anchor` / `hive_place_unit_clipboard` / `hive_unit_clipboard_id` / `hive_model_from_unit_clipboard`。前端记住复制时的对象类型，粘贴时走对应的那套。

## 4.17 单位和单位放置

```c
int32_t hive_unit_type_count(void* handle);
const char* hive_unit_type_id(void* handle, int32_t index);
int32_t hive_add_unit(void* handle, const char* id, float x, float y, float angle, int32_t player);
```

类型列表取 `Units.slk` 的行头，836 个。放置走 `Units::add_unit(id, position)`：它负责绑模型、建骨骼、发 `creation_number`、调一次 `update()`。设完 `angle` 和 `player` 要再调一次 `update()`，因为朝向参与骨架的旋转计算。

高度在放置时贴地形，角度照 HiveWE 的 `UnitBrush::apply` 直接赋值，不做吸附 —— 单位的朝向不受 `fixedrot` 和路径图约束，那是装饰物才有的规则。

`add_unit` 之前要先确认 `get_mesh(id)` 拿得到模型，上游不判空。testdata 只是客户端的子集，很多单位模型不在里面，点下去会返回 -1 而不是崩。

整组放置进一个 `UnitAddAction`，一次 Ctrl+Z 收掉。这个 action 的 undo 同样是 `resize(size - n)`。

## 4.18 对象属性

对应 HiveWE 的对象编辑器。分类和它一致：0 单位、1 物品、2 装饰物、3 可破坏物、4 技能、5 升级、6 buff。

```c
int32_t hive_object_field_count(void* handle, int32_t category, const char* id);
int32_t hive_doodad_category(void* handle, const char* id);
const char* hive_object_field_key(void* handle, int32_t category, int32_t index);
const char* hive_object_field_label(void* handle, int32_t category, int32_t index);
const char* hive_object_field_type(void* handle, int32_t category, int32_t index);
const char* hive_object_field_description(void* handle, int32_t category, int32_t index);
const char* hive_object_value(void* handle, int32_t category, const char* id, int32_t index);
int32_t hive_set_object_value(void* handle, int32_t category, const char* id, int32_t index, const char* value);
int32_t hive_object_value_modified(void* handle, int32_t category, const char* id, int32_t index);
```

字段清单照 `SingleModel::buildMapping` 生成：

- 遍历 meta slk 的行，`useSpecific` 非空且不含当前 id（以及 `code` 别名）的跳过；`notSpecific` 含当前 id 的也跳过。单位表这一列全是空的，装饰物表根本没有这一列。
- 列名 = `field` 列转小写，带 `data` 的补 a/b/c 后缀。带 `repeat` 的按 `levels` / `numvar` / `maxlevel` 展开成多条，编到第几级也进显示名。
- 表里没有的列用 `SLK::add_column` 补一个空列，否则写不进去。
- 排序按「分类 - 显示名 + 列名」，分类名从 `UI/WorldEditData.txt` 的 `ObjectEditorCategories` 取。

读值走 `SLK::data`，改过的值优先；写值走 `SLK::set_shadow_data`，落在这张表的 shadow 层。保存时 `save_modification_file` 把 shadow 里非空的行写成 `war3map.w3u` / `.w3d` / `.w3b` / `.w3t` 等。

改过的字段记在 shadow 里，界面上显示成紫色。

地图里的装饰物 id 可能属于 `Doodads.slk` 也可能属于 `DestructableData.slk`（树基本都是后者），`hive_doodad_category` 按这个顺序判断，面板据此选对分类。

### 自定义对象

```c
int32_t hive_create_object(void* handle, int32_t category, const char* source_id, const char* new_id);
int32_t hive_delete_object(void* handle, int32_t category, const char* id);
int32_t hive_object_is_custom(void* handle, int32_t category, const char* id);
const char* hive_unique_object_id(void* handle, const char* source_id);
```

新建走 `SLK::copy_row(source, new, true)`：整行复制到 base 层，shadow 里记 `oldid`，这就是 HiveWE 存的「这个对象基于谁」。保存时 `save_modification_table` 按 `oldid` 有没有把行分到自定义段和修改段两部分写。

`hive_unique_object_id` 用上游的 `get_unique_id`，查遍七张表避开已占用的 id，首字母大小写跟原型一致（单位小写、装饰物大写）。

新建和删除都要清掉 `doodad_types` / `unit_types` 缓存和字段缓存，否则下拉和面板还拿旧列表。

界面入口在属性面板顶部：「复制为新对象」弹窗填 4 字符 id（默认已生成），「删除自定义」只对带 `oldid` 的行生效。

## 4.19 地图信息

```c
const char* hive_map_name(void* handle);
int32_t hive_set_map_name(void* handle, const char* value);
const char* hive_map_author(void* handle);
const char* hive_map_description(void* handle);
const char* hive_map_suggested_players(void* handle);
void hive_map_versions(void* handle, int32_t* out);
void hive_map_playable_size(void* handle, int32_t* width, int32_t* height);
```

名称、作者、描述、建议玩家在 `war3map.w3i` 里存的是 `TRIGSTR_xxx` 键，实际文本在 `war3map.wts`。读写都走 `TriggerStrings`：读用 `string()` 拿解析后的文本，写用 `set_string()`，键为空时它会自己分配一个新编号。

界面在顶部工具条的「地图信息」，弹出的框里四个字段可改，尺寸和版本只读，底部四边的增量框可以改地图大小。

### 改尺寸

```c
int32_t hive_resize_map(void* handle, int32_t delta_left, int32_t delta_right, int32_t delta_top, int32_t delta_bottom);
int32_t hive_set_playable_area(void* handle, int32_t left, int32_t right, int32_t top, int32_t bottom);
```

`Map::resize` 把地形、路径图、阴影图、装饰物、单位、区域全部按增量重排，所有对象坐标跟着平移，撤销栈清空（原版 WE 的行为）。新的边长要落在 32..480，`Map::resize` 里那两条 `assert` 在 Release 下不生效，所以桥接层先自己判一遍。

改完尺寸，`TerrainView` 的顶点数、纹理层、MultiMesh 实例全部作废。`Main` 里把「关掉场景树 → 重置状态 → 重新建」拆成 `CloseEditor` / `ResetEditorState` / `BuildEditor` 三步，`LoadMap` 和改尺寸共用，区别只在要不要重新 `HiveCore.Open`。

## 4.20 触发器

`war3map.wtg` 由 `Triggers::load` 解析成三张列表：分类、触发器、变量，都靠 `parent_id` 组树（顶层是 0，Map Header 自己的 id 就是 0）。

```c
int32_t hive_trigger_category_count(void* handle);
int32_t hive_trigger_count(void* handle);
const char* hive_trigger_name(void* handle, int32_t index);
int32_t hive_trigger_is_enabled(void* handle, int32_t index);
int32_t hive_trigger_eca_count(void* handle, int32_t index, int32_t type);
const char* hive_trigger_eca_name(void* handle, int32_t index, int32_t type, int32_t eca);
int32_t hive_set_trigger_name(void* handle, int32_t index, const char* value);
```

一个触发器的 ECA（事件/条件/动作）全存在 `Trigger::ecas` 里，靠 `ECA::type` 区分，接口按 type 过滤后再按顺序取。

参数个数不是存在 wtg 里的，而是解析时从 `UI/TriggerData.txt` 的 `[TriggerActions]/[TriggerEvents]/[TriggerConditions]/[TriggerCalls]` 段按「逗号分隔里非空、非数字、非 nothing 的项数」算出来，再 `resize` 参数数组。`TriggerCalls` 要减一（第一个字段是返回类型）。所以换客户端版本必须先有对应的 `TriggerData.txt`，否则参数全部解析成 0 个，后面的读取会错位。

界面在顶部工具条的「触发器」，左边是分类与触发器组成的树，右边是名称、启用、初始开启、描述和只读的 ECA 清单。改名称或描述直接写回内存，Ctrl+S 存进 wtg。

## 5. 界面

### 5.1 结构

```
Main (Node3D)
└── root (Node3D)              换地图时整个删掉重建
    ├── TerrainView (Node3D)   地形 MultiMesh、水面 MultiMesh、灯光、环境
    ├── Camera3D               固定俯角，平移缩放
    ├── 笔刷高亮 (MeshInstance3D)
    └── EditorUi (CanvasLayer)
        ├── 左侧面板           纹理墙、工具按钮、对象下拉、笔刷尺寸与形状、小地图
        ├── 顶部工具条         当前工具、打开、撤销重做、保存
        └── 状态栏             鼠标位置、笔刷尺寸、水面格数
```

界面全部用代码搭，没有 `.tscn` 里的控件树。`Main.cs` 只管事件与协调，地形渲染在 `TerrainView.cs`，控件在 `EditorUi.cs`。

左侧面板宽 232 px，顶部工具条与状态栏都从 232 起，视口是剩下的区域。面板上的点击被 Control 吃掉，不会漏到 3D 视口，因为鼠标事件走 `_UnhandledInput`。

### 5.2 数据流

改动是单向的，不绑定：

```
用户操作 → EditorUi 事件 → Main → HiveCore（C ABI）→ 核心改数据
                                        ↓
                              TerrainView.Reload() 重新拉一遍
                                        ↓
                        高度图重传 + 18432 份实例数据 + 小地图重画
```

`Reload` 每次全量拷贝，193×97 的图大约 2 ms。笔刷拖动时每次鼠标移动都走一遍，够用。区域级增量更新留到帧率不够时再做。

### 5.3 面板

| 面板 | 状态 |
|---|---|

## 6. 渲染

`render/` 不参与编译，画面由 C# 用 Godot 节点画。

### 6.1 地形

`MultiMesh`，每 tile 一个实例，18432 个。顶点位置来自 `MODEL_MATRIX` 的平移分量，高度从一张 `Rf` 高度图采样：

```glsl
vec2 tile = MODEL_MATRIX[3].xz;
VERTEX.y = texture(height_map, (tile + UV) / (vertex_size - 1.0)).r;
```

四角纹理索引在 `INSTANCE_CUSTOM` 里，已经换算成 `Texture2DArray` 的绝对层号。混合照抄 `data/shaders/terrain.frag`：

```glsl
vec4 color = texture(ground_tex, vec3(UV, layers.w));
color = mix(texture(ground_tex, vec3(UV, layers.z)), color, color.a);
color = mix(texture(ground_tex, vec3(UV, layers.y)), color, color.a);
color = mix(texture(ground_tex, vec3(UV, layers.x)), color, color.a);
```

从最底层往上 mix，每步用当前颜色的 alpha 当覆盖度。空角指向数组末尾一层全透明。

纹理数组共 224 层（7 张 × 32 变体 + 1 层空），每层 64×64。

图块数据来自 `GroundTexture`。它在构造时把大图切成 16 或 32 块，本来切完就丢、只上传 GPU，补丁里加了 `stored_tiles` 留一份 CPU 副本，C ABI 才取得到。`width == height * 2` 时走 extended 分支切 32 块，BootyBay 的 7 张全是 32 块。

### 6.2 水面

第二个 `MultiMesh`，实例数和地形一样，没水的实例把 `Basis` 缩成 0 隐藏。四个角的水面高度塞进 `INSTANCE_CUSTOM`，顶点着色器按 UV 双线性插值，再加一个随时间走的正弦波。

`INSTANCE_CUSTOM` 在 Godot 里只能在 `vertex()` 里直接用，套一层自定义函数会报 `Unknown identifier`。

### 6.3 拾取

不用物理引擎，直接沿射线步进：每步取当前点的高度，落差大就跨大步、落差小就小步，第一次低于地面就停。512 步上限，够穿整张图。

比加碰撞体便宜，也不用给 MultiMesh 建 `ConcavePolygonShape3D`。

### 6.4 笔刷高亮

方形和菱形用一张 `QuadMesh` + 半透明材质，位置贴到笔刷格子的中心。圆形时直接隐藏 —— 方形框配圆笔刷会误导。真要做成圆形高亮，可以再画一个 MultiMesh 铺笔刷的 mask。

### 6.5 装饰物

静态摆放，不带骨骼动画。解析出来的 MDX 顶点做成 `ArrayMesh`：每个 geoset 一个 surface，双面材质按 `two_sided` 标志、`unshaded` 走无光照、贴图开 alpha scissor 处理树叶。

按模型分组建 `MultiMesh`，62 个模型对应 62 个 `MultiMeshInstance3D`。

### 6.6 还没做的

骨骼动画（现在只摆静态网格）、单位按玩家上色、放置带路径图的装饰物后重算路径图叠加层。

## 7. 工程组织

```
HiveWeGodot/
├── native/
│   ├── _upstream/          HiveWE 原仓库（不进库，tools/fetch_upstream.sh 拉）
│   ├── src/                转换产物：95 个 .hpp + 67 个 cpp + 52 个头文件
│   ├── include/            Qt 兼容层与第三方替身
│   ├── CMakeLists.txt      hivewe_core 静态库
│   └── build/              libhivewe_core.a（不进库）
├── third_party/            vma / vkbootstrap / ankerl（脚本拉，不进库）
├── testdata/
│   ├── maps/               测试地图，w3m 原文件
│   └── warcraft/           从游戏 MPQ 里按实际访问清单提取的资源子集
├── tools/
│   ├── decomod.py          去模块化
│   ├── fetch_upstream.sh   按固定 commit 拉源码
│   └── fetch_third_party.sh
└── godot/                  Godot C# 工程
```

`native/src` 是生成物，但进库：改动都写在 `decomod.py` 的补丁表里，重新生成时自动套用，看代码不用先跑脚本。

`testdata/warcraft` 是从完整客户端里挑出来的一份资源，25 MB，覆盖 `testdata/maps` 下那几张地图加载时需要读的全部 slk、模型、贴图。加载时走 `hierarchy` 的 `local_files` 分支读这个目录，不需要安装 Warcraft III。

重建方式：把完整客户端目录传进去，程序跑一遍记录访问过的文件，再按清单提取。

```bash
./tools/extract_testdata.sh "/path/to/Warcraft III"
```
