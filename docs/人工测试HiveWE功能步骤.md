# 人工测试 HiveWE 功能步骤

这份文档用来逐项体验当前实现，确认行为符合预期。每条给入口、操作和预期结果，测过的打勾。发现不符的记下条目编号和实际现象。

自动检查在 `tools/run_native_tests.sh`（40 个原生测试）和各窗口的 `--headless` 用例里，它们只验数据层。界面布局和手感靠这份文档逐条点过去。

## 0. 准备

- [ ] 准备一份 1.27 客户端目录，里面要有 `WAR3.MPQ`
- [ ] 准备一张测试地图，建议 `(2)BootyBay.w3m`
- [ ] 从源码跑：`/Applications/Godot_mono.app/Contents/MacOS/Godot --path godot`
- [ ] 或者用打包版：`bash tools/export-macos.command`，产物在 `godot/HiveWeGodot.app`

源码运行时启动后直接打开 `testdata/maps/(2)BootyBay.w3m`。打包版第一次启动会弹目录选择，选客户端目录；之后启动打开上次的地图，没有就新建一张 65×65 空白图。

## 23. 已知差异

这些和上游 HiveWE 表现不同，属于当前实现的状态，不算缺陷：

| 现象 | 说明 |
|---|---|
| 同类单位的动作彼此同步 | 单位和装饰物按模型分组共用一个网格，组内共用一帧，组之间错开相位。上游每个实例独立走帧 |
| 装饰物不动 | 主视图的装饰物是静态姿态，没有动画循环 |
| 线框在导出包里无效 | 用的是 Godot 的 `Viewport.DebugDraw`，只有调试构建才画线框 |
| 队伍 / 兵种树 / 技能 / 升级属性没有编辑界面 | 上游这几个页签也是空的，只有玩家属性页有逻辑 |
| 没有「测试地图」按钮 | 上游会调 War3 启动，本工程不启动外部进程 |
| 没有资产管理器和导入管理器 | 上游没有对应界面 |
